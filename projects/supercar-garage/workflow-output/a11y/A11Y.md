## Initial Violations Found (Pre-Fix)

Axe impact levels map to WCAG severity: P1 (highest), P2 (high), P3 (moderate), P4 (minor).

### P1 - axe impact: label (1 rule, 8 instances)

**label** - Ensure every form element has a label
- Every page: `<input type="checkbox" name="newsletter-optin" value="true">`
- Root cause: the checkbox was wrapped in a `<label>` element but the label had no text content when the `newsletterConsentLabel` prop was not populated in content. An empty wrapping `<label>` does not provide an accessible name.
- Impact: screen reader users could not identify the newsletter consent checkbox purpose.

### P2 - axe impact: color-contrast (1 rule, 6 instances across 2 pages)

**color-contrast** - Foreground/background contrast below WCAG AA 4.5:1 threshold

**Instance group 1 - Facet filter selects (actualites page):**
- `#facet-select-themes-actualites` and `#facet-select-type`
- Foreground: #6d6e76 (browser-default grey option text), Background: #080807 (site dark bg)
- Measured ratio: 3.95:1 (required: 4.5:1)

**Instance group 2 - Navigation level1 submenu links (annonce press release page):**
- `.level1.submenu.item > .navigation-title.field-navigationtitle > a` (4 nav items)
- Foreground: #080807, Background: #000000 (page body)
- Measured ratio: 1.04:1 (required: 4.5:1)
- Root cause: the vendor theme CSS used `color: var(--color-bg)` for level1 nav links. On this dark-themed site `--color-bg = #080807` (near-black), producing near-invisible text against the dark transparent header/body.

## Fixes Applied

### Fix 1 - Newsletter checkbox accessible name

**File:** `src/components/Shell/FooterSection/default.server.tsx`

Added `aria-label` directly to the checkbox element as a guaranteed fallback. When `newsletterConsentLabel` is empty (content not yet populated), the checkbox now always has an accessible name via `aria-label`. When `newsletterConsentLabel` is populated, both the implicit label text and the `aria-label` identify it.

```tsx
<input
  type="checkbox"
  name="newsletter-optin"
  value="true"
  aria-label={props.newsletterConsentLabel ?? "J'accepte de recevoir la newsletter"}
/>
```

### Fix 2 - Facet filter select color contrast

**File:** `src/components/Listing/FacetFilter/default.server.tsx`

Added inline `style` on the `<select>` element to force white text on the dark background. The browser-default grey placeholder color (#6d6e76) is replaced with #ffffff which achieves >7:1 contrast on #080807. Options are explicitly styled with dark text on white background for readability when the dropdown is open.

```tsx
style={{ color: "#ffffff", backgroundColor: "#080807" }}
```

**File:** `src/components/Listing/FacetFilter/component.module.css`

Added `:global(.facet-dropdown-select)` and `:global(.facet-dropdown-select option)` rules as a CSS-layer backup.

### Fix 3 - Navigation level1 submenu link color

**File:** `src/components/Shell/MainNavigation/mainNavigation.module.css`

Added `:global()` overrides to correct two related contrast issues:

1. Level1 desktop nav links: `color: #ffffff !important` so white text is visible against the dark transparent header and dark body background (#080807).
2. Level1 submenu dropdown: `background-color: #ffffff !important` to explicitly set a white background on the dropdown panel, so the level2 dark link text (#1a1a1a) achieves >7:1 contrast.
3. Mobile media query exception: level1 link color reverts to #080807 in the mobile nav panel which has its own white background.
